00The one-paragraph mental model

Before any algebra: what is the machine actually doing?

BERT is a function that refines a sequence of vectors, in place, twelve times.

You hand it T tokens. It converts each into a 768-dimensional vector. Then it runs the same two-step refinement twelve times over:

  1. Mix across positions (self-attention). Each vector is replaced by a weighted average of all the vectors, where the weights are computed from the vectors themselves.
  2. Refine each position independently (feed-forward network). Every vector goes through the same two-layer MLP, with no communication between positions.

That is the whole architecture. Attention moves information sideways across the sequence; the FFN processes information vertically at each position. Alternate them twelve times and you have BERT.

The residual stream picture The most useful frame: there is a single T × 768 tensor — the residual stream — that persists from the embedding layer to the output. Attention and FFN blocks don't transform it; they read from it and add to it. Every sublayer is x = x + f(x). Nothing overwrites; everything accumulates. This is why you can delete a middle layer of a trained BERT and it still mostly works, and why linear probes at layer k are meaningful.

What BERT is not

Not a generator

BERT is encoder-only and bidirectional. Position 5 attends to position 40. There is no causal mask, so it cannot be sampled left-to-right. It produces representations, not text. GPT is decoder-only with a causal mask; T5 is both.

Not a sentence-embedding model (out of the box)

The [CLS] vector of a raw pre-trained BERT is a notoriously poor sentence embedding — cosine similarity between two of them is nearly meaningless because the embedding space is highly anisotropic. That's what Sentence-BERT and contrastive fine-tuning exist to fix.

01Tokenization — WordPiece

Before a single matrix multiply, text becomes integers. This step is lossy, opinionated, and responsible for more downstream bugs than any layer of the network.

The algorithm

BERT uses WordPiece with a 30,522-entry vocabulary. Given a whitespace-and-punctuation pre-tokenised word, it runs greedy longest-match-first:

def wordpiece(word, vocab, max_chars=100):
    if len(word) > max_chars: return ["[UNK]"]
    tokens, start = [], 0
    while start < len(word):
        end, cur = len(word), None
        while start < end:                       # shrink from the right
            sub = word[start:end]
            if start > 0: sub = "##" + sub        # continuation marker
            if sub in vocab: cur = sub; break
            end -= 1
        if cur is None: return ["[UNK]"]      # whole word fails if any piece fails
        tokens.append(cur); start = end
    return tokens
Two details people get wrong (1) The ## prefix marks continuation, not the start of a word. play and ##play are different vocabulary entries with different embeddings. (2) Failure is all-or-nothing per word. If any piece of a word is unmatchable the entire word becomes a single [UNK] — you do not get a partial tokenization.

Why add and not concatenate?

Concatenating token, position, and segment vectors would give each its own private subspace — cleaner, arguably. But it would force dmodel to grow, and every downstream weight matrix with it. Addition keeps the model width fixed, and the network learns to separate the summed signals in different subspaces anyway, because 768 dimensions is far more capacity than 3 signals need.

Superposition This is a specific instance of a general phenomenon: transformers routinely store many more features than they have dimensions, in almost-orthogonal directions. In 768 dimensions you can pack thousands of directions with pairwise cosine similarity under 0.1. Addition works because interference is small and the network can learn to tolerate it.

Learned positions: the 512 wall

Because positions are a learned lookup table with 512 rows, BERT cannot process a 513rd token. There is no row to look up. This is a hard architectural limit, unlike sinusoidal encodings (which extrapolate, badly) or RoPE/ALiBi (which extrapolate meaningfully better).

03Self-attention — the only part that mixes positions

Everything else in the transformer operates on one position at a time. This is the only mechanism by which token 3 can ever learn about token 40.

The equation, and what each symbol is doing

Attention(Q, K, V) = softmax( QK⊤ / √dk + M ) V Q, K ∈ RT×dk  •  V ∈ RT×dv  •  M = additive mask (0 or −∞)

Query — "what am I looking for?"

Q = XWQ. Each row is one token's search request. It is projected from that token's own current residual-stream vector.

Key — "what do I advertise?"

K = XWK. Each row is one token's index entry. The dot product qi·kj measures how well token j's advertisement matches token i's request.

Value — "what do I contribute?"

V = XWV. The payload actually mixed into the output. Crucially decoupled from K: a token can be easy to find but contribute something unrelated to why it was found.

Why Q and K are separate matrices If you used XX⊤ the attention matrix would be symmetric and forced positive on the diagonal — every token would attend mostly to itself, and "A modifies B" could not differ from "B modifies A". Separate WQ and WK make the score matrix asymmetric, which is exactly what you need for directional linguistic relations. Note also that only the product WQWK⊤ matters mathematically — it is a single low-rank bilinear form of rank ≤ dk, factored into two matrices for parameter efficiency.

The √dk scaling — not cosmetic

Assume the entries of q and k are independent with mean 0 and variance 1. Their dot product is a sum of dk such products, so:

Var(q · k) = Var( Σi=1..dk qiki ) = dk  ⇒  sd = √dk for dk = 64, raw scores have sd 8 — softmax over values spread ±24 is nearly one-hot

A saturated softmax has vanishing gradients: ∂softmaxi/∂sj = pi(δij − pj), which goes to zero when any pi → 1. Dividing by √dk restores unit variance and keeps the distribution in a trainable regime.

An underrated consequence Scaling also controls entropy at initialisation. With correct scaling, a randomly initialised head produces a near-uniform attention distribution — effectively "average everything", a sane starting point. Without it, random heads start out committed to essentially arbitrary tokens and must first unlearn that commitment through a nearly flat gradient. This is a large part of why unscaled attention trains so badly.

04Multi-head attention — the same cost, more relations

One attention head can express one weighted-average pattern per position. Twelve heads express twelve simultaneously — for the same FLOPs.

The reshape that does all the work

Multi-head attention is not twelve separate attention modules. It is one set of projections whose output is reshaped so that the batched matmul treats heads as an extra batch dimension:

# B=batch, T=seq, H=768 (d_model), A=12 heads, d_k = H/A = 64
q = self.query(x)                        # (B, T, 768)  -- ONE matmul, not 12
q = q.view(B, T, 12, 64).transpose(1, 2)   # (B, 12, T, 64)
# ... same for k, v ...

scores = q @ k.transpose(-2, -1) / math.sqrt(64)   # (B, 12, T, T)
scores = scores + attention_mask                        # broadcast (B,1,1,T)
probs  = scores.softmax(dim=-1)                       # normalise over KEYS
probs  = self.dropout(probs)                            # yes, dropout on attention weights

ctx = probs @ v                          # (B, 12, T, 64)
ctx = ctx.transpose(1, 2).reshape(B, T, 768)  # concat heads back
out = self.output_dense(ctx)             # (B, T, 768)  W^O -- essential, see below
The single most common bug in from-scratch implementations softmax(dim=-1). The softmax normalises over the key axis, so each query row sums to 1. Using dim=-2 normalises over queries instead — the code runs, the shapes are identical, the loss even decreases somewhat, and the model is quietly wrong. Always assert probs.sum(-1) ≈ 1.

Why WO is not optional Without the output projection, concatenating heads would leave each head writing into a fixed, disjoint 64-dimensional slice of the residual stream. WO lets every head write to any direction in the 768-d space, and lets heads' outputs be linearly combined before being added back. Equivalently: attention is a sum over heads of softmax(·) V WO[head slice] — each head has its own independent WVWO "output circuit."

What individual heads actually learn

Probing studies (Clark et al. 2019; Voita et al. 2019) find heads specialise into recognisable, reusable patterns — and that a majority can be pruned with little loss, which tells you the redundancy is high.

The [SEP] / [CLS] sink A large fraction of heads in a trained BERT dump most of their attention mass on [SEP], [CLS], or punctuation. This is widely believed to be a no-op mechanism: softmax must sum to 1, so a head that has nothing useful to contribute at a given position needs somewhere harmless to put its probability mass. Modern architectures sometimes add an explicit learned "attention sink" or off-by-one softmax for precisely this reason — and it materially improves activation-outlier behaviour for quantization.

05Masking — the additive −∞ trick

Padding must be invisible to attention. The implementation is a small piece of numerical engineering that is easy to get subtly wrong.

You cannot simply zero out attention weights after the softmax — the remaining weights would no longer sum to 1. Instead the mask is added to the scores, before the softmax:

# attention_mask from tokenizer: (B, T) with 1 = real token, 0 = pad
ext = attention_mask[:, None, None, :]        # (B, 1, 1, T) -> broadcasts over heads & queries
ext = (1.0 - ext) * torch.finfo(dtype).min       # 1 -> 0.0 ,  0 -> -3.4e38 (fp32)
scores = scores + ext
probs  = scores.softmax(dim=-1)                   # e^(-inf) = 0, and rows still sum to 1

Use dtype.min, not −1e9 In fp16 the maximum finite value is 65504, so −1e9 becomes −inf, and −inf + −inf or a fully-masked row produces NaN after softmax. Always use torch.finfo(scores.dtype).min. A fully-masked row (an all-padding example) still yields NaN even then — guard against zero-length inputs.
BERT has no causal mask This is the defining architectural difference from GPT. Every position sees every other position, in both directions, at every layer. That bidirectionality is precisely why BERT needs a masked pre-training objective: with full visibility, next-token prediction is trivially solved by copying.

06Add & Norm — residuals and LayerNorm

Two lines of code that make 12-layer training possible at all. BERT's specific ordering of them is also the reason it needs a learning-rate warmup.

The residual connection

xℓ+1 = xℓ + Sublayer(xℓ)

The gradient of the sum with respect to xℓ contains an identity term, so ∂L/∂xℓ = ∂L/∂xℓ+1 · (I + ∂Sublayer/∂x). Even if the sublayer Jacobian is tiny, gradient still flows through the identity path. Empirically this is what allows 12, 24, or 96 layers to train.

LayerNorm — and why not BatchNorm

LN(x) = γ ⊙ (x − μ) / √(σ² + ε) + β μ, σ² computed over the feature axis (768 values), independently for every token

Variable-length sequences are the killer. BatchNorm's statistics would be computed over a mix of real tokens and padding, and would change with batch composition — making inference non-deterministic in batch size. LayerNorm is per-token and completely independent of batching.

Post-LN vs Pre-LN — BERT made the older choice

Post-LN BERT

x = LayerNorm( x + Sublayer(x) )

LayerNorm sits on the residual path, so gradients are rescaled at every layer. Deep stacks suffer gradient magnitude blow-up early in training. Requires learning-rate warmup (BERT uses 10k steps) — remove it and training diverges. This is not folklore; it is a well-characterised failure.

Pre-LN GPT-2+, most modern models

x = x + Sublayer( LayerNorm(x) )

The residual path is a clean identity from input to output — no normalisation on it at all. Much more stable, trains without warmup, scales to hundreds of layers. Slightly worse final quality at equal depth in some studies, which is why the switch took a while.

07The feed-forward network — two thirds of the parameters

Attention gets all the attention. The FFN holds 66% of the non-embedding parameters and is increasingly understood to be where factual knowledge lives.

FFN(x) = GELU( x W1 + b1 ) W2 + b2 W1 ∈ R768×3072 • W2 ∈ R3072×768 • 4× expand, then project back

Applied independently and identically at every position — it is a 1×1 convolution over the sequence. No position talks to any other inside the FFN. Per layer: 2 × 768 × 3072 + 3072 + 768 = 4,722,432 parameters, versus 2,362,368 for all of attention. Two-to-one.

GELU, and why not ReLU

GELU(x) = x · Φ(x) = x · ½[1 + erf(x/√2)] tanh approximation: 0.5x(1 + tanh[√(2/π)(x + 0.044715x³)])

Read it as a stochastic-regulariser-in-expectation: instead of gating on the sign of x (ReLU) or on a Bernoulli coin (dropout), GELU multiplies x by the probability that a standard normal is below it. Small positive values get partially suppressed; small negative values are not hard-zeroed. The result is smooth and non-monotonic, with a small negative dip around x ≈ −0.75.

The FFN as key–value memory Geva et al. (2021) showed the FFN behaves like a lookup table. W1's 3072 columns are keys: xW1 scores the current residual vector against 3072 learned patterns. W2's 3072 rows are values: the output is a GELU-weighted sum of them, added back to the residual stream. Individual columns respond to interpretable inputs ("this is a date", "the subject is a country"). This is the mechanism ROME and MEMIT edit when they perform surgical fact editing on a language model — they rewrite specific rows of W2 in a single mid-stack layer.

Why exactly 4×?

Empirical, not derived. The ratio dff/dmodel = 4 comes from the original Transformer and has stuck because it sits near a flat optimum: 2× underperforms noticeably, 8× buys little for double the cost. Modern gated variants (SwiGLU in LLaMA, PaLM) use three matrices instead of two and shrink the hidden width to 8/3 × dmodel to hold the parameter count roughly constant — and beat the plain 4× FFN at equal parameters.

08Assembling one encoder block

Everything so far, wired together. This is BertLayer in full — and it repeats identically twelve times with no weight sharing.

class BertLayer(nn.Module):
    def forward(self, x, mask):
        # ---- sublayer 1: multi-head self-attention -------------------
        a = self.attention(x, mask)          # (B,T,768)
        a = self.attn_output_dense(a)        # W^O
        a = self.attn_dropout(a)             # p = 0.1
        x = self.attn_layernorm(x + a)       # <-- POST-LN: residual THEN norm

        # ---- sublayer 2: position-wise feed-forward ------------------
        h = self.intermediate_dense(x)       # (B,T,3072)
        h = gelu(h)
        h = self.output_dense(h)             # (B,T,768)
        h = self.ffn_dropout(h)              # p = 0.1
        x = self.ffn_layernorm(x + h)        # <-- POST-LN again
        return x

09The stack — what the twelve layers actually do

Probing studies find a surprisingly consistent progression from surface form to syntax to semantics, roughly recapitulating the classical NLP pipeline.

📊Widget 15 — layer-wise probing profile

Click a linguistic task to see where in the stack a linear probe on the frozen hidden states performs best. Curve shapes follow Tenney et al. (2019), "BERT Rediscovers the Classical NLP Pipeline"; values are illustrative.

Layers 1–4 — surface

Token identity, word shape, positional patterns, local n-gram statistics. Representations here are still close to the input embeddings; cosine similarity to the embedding vector is high.

Layers 5–8 — syntax

POS, constituency and dependency structure, agreement. Hewitt & Manning showed a linear transformation of these states embeds the dependency parse tree such that squared L2 distance recovers tree distance.

Layers 9–12 — semantics & task

Coreference, semantic roles, entity types, and increasingly objective-specific features. The last one or two layers are heavily specialised toward MLM and often worse for transfer than layer 9–10.

Practical consequence for fine-tuning The final layer is not automatically the best feature extractor. For frozen-feature use, concatenating layers 9–12 or taking layer −2 frequently beats layer −1. And when fine-tuning, layer-wise learning-rate decay (lower LR for early layers, e.g. a factor of 0.9 per layer going down) is a reliable half-point on most GLUE tasks — early layers encode general features you do not want to disturb.

10Pre-training — MLM and NSP

The architecture is only half of BERT. The other half is a training objective that requires bidirectionality — which is the actual contribution of the paper.

Masked Language Modelling

Select 15% of token positions. For each selected position, apply the 80/10/10 rule and predict the original token at that position from the final hidden state. Loss is cross-entropy over the 30,522-way vocabulary, computed only at selected positions.

80% → [MASK]

The main signal. Forces the model to use bidirectional context to reconstruct a missing token.

10% → random token

Forces the model to build a good representation of every token, not just masked ones — because any token might be corrupted and need correcting.

10% → unchanged

Biases the representation toward the observed token, and closes part of the pre-train/fine-tune gap — at fine-tuning time nothing is ever masked.

Why the 80/10/10 split exists at all If masking were 100% [MASK], the model would only ever learn to build good representations at positions carrying the [MASK] embedding. At fine-tuning time that token never appears, so every representation would be off-distribution. The 10% random / 10% unchanged arms mean the model cannot tell which positions it will be scored on, so it must represent all of them well. This is a train/test-distribution fix, not a regularisation trick — and ELECTRA later removed the problem entirely by never masking.

Next Sentence Prediction — and why it was removed

Binary classification from the [CLS] vector: is segment B the actual continuation of segment A, or a random sentence from another document? 50/50 positive/negative.

NSP turned out to be nearly useless RoBERTa (Liu et al. 2019) showed NSP contributes little or nothing, and that removing it while training on full-length contiguous sequences is strictly better. The likely reason: the negative pairs come from different documents, so the task is solvable by topic detection alone — the model never has to learn discourse coherence. ALBERT replaced it with SOP (sentence-order prediction: same two consecutive sentences, swapped or not), which removes the topic shortcut and does help.

The 15% budget is the real inefficiency MLM computes a full forward pass over T tokens but derives a learning signal from only 0.15T of them. ELECTRA's discriminator gets signal from every position, which is why it matches RoBERTa quality at roughly a quarter of the compute. If you are pre-training from scratch today, this is the first thing to consider.

11Task heads — fine-tuning

The encoder is task-agnostic. Everything task-specific lives in a head that is usually one linear layer.

The pooler, and why you probably shouldn't use it

# BertPooler -- applied to the [CLS] token only
pooled = torch.tanh(self.dense(hidden_states[:, 0]))   # (B, 768) -> (B, 768)
The pooler was trained by NSP, and NSP was useless Those 590,592 parameters were optimised for exactly one thing: next-sentence prediction. Since NSP turned out to contribute almost nothing, the pooler's weights encode almost nothing useful. Most strong fine-tuning recipes bypass it entirely and put the classification head directly on hidden_states[:, 0], or on a mean-pool over non-padding tokens — which for sentence-level similarity is usually better still.

12Applied: cross-encoders vs bi-encoders

The single most important architectural decision when you use BERT for ranking or matching — and it is entirely about when the two inputs are allowed to attend to each other.

Cross-encoder

[CLS] query [SEP] document [SEP]
  → BERT → [CLS] → Linear → score

Every query token attends to every document token at every one of the 12 layers. Term-level interaction is available throughout.

  • Highest accuracy by a wide margin
  • One forward pass per pair
  • Nothing is precomputable
  • Practical ceiling: ~100–200 candidates

Bi-encoder

BERT(query) → u   BERT(doc) → v
  score = u · v

The two inputs never see each other. All interaction is compressed into a single dot product at the end.

  • Document vectors precomputed & indexed
  • ANN search over billions, sub-millisecond
  • Loses fine-grained term matching
  • The standard first-stage retriever

Late interaction — the middle of the curve ColBERT keeps per-token document embeddings and scores with Σi∈q maxj∈d (qi · dj) — the MaxSim operator. Document representations are still precomputable, but token-level matching survives. Cost sits between the two extremes: roughly 10–30× the storage of a bi-encoder, roughly 100× cheaper than a cross-encoder. If your cross-encoder is the latency bottleneck and a bi-encoder is not accurate enough, this is the axis to move along.

Distilling the cross-encoder into the retriever

The standard modern recipe, and the highest-leverage single move in a two-stage system: use the cross-encoder as a teacher to train the bi-encoder. Two loss forms dominate:

Margin-MSE:  L = ( [sT(q,d⁺) − sT(q,d⁻)] − [sS(q,d⁺) − sS(q,d⁻)] )² match score differences, not absolute scores — ranking only needs relative order KL / listwise:  L = KL( softmax(sT/τ) ‖ softmax(sS/τ) ) match the teacher's full distribution over a candidate list

The teacher can also label enormous volumes of unlabelled query–document pairs, which is usually a bigger win than any architectural change — it removes the human-annotation bottleneck entirely.

When does the quadratic term actually bite? Attention cost overtakes FFN cost when 4T²H > 24TH², i.e. T > 6H. For BERT-base that is T > 4608 — far past the 512 limit. At BERT's actual sequence lengths, attention is not the bottleneck; the FFN matmuls are. The quadratic term dominates memory long before it dominates FLOPs, though: the (B, A, T, T) attention matrix at B=32, T=512 is 32×12×512×512×4 bytes = 402 MB for a single layer's activations. That is what FlashAttention eliminates by never materialising it.

15Field notes — things that silently go wrong

Failure modes that produce no error message and no stack trace.

Tokenizer / checkpoint mismatch

Loading bert-base-cased weights with an uncased tokenizer runs cleanly and returns nonsense. Token IDs index into a different vocabulary, so every embedding lookup is wrong. Always load both from the same directory, and assert len(tokenizer) == model.config.vocab_size.

Forgetting the attention mask

Without it, real tokens attend to [PAD], and the pad embedding leaks into every representation. Worse: results become batch-composition dependent, because padding length depends on the longest sequence in the batch. Symptom: the same input scores differently in different batches. This alone accounts for a large share of "my model is non-deterministic" reports.

Mean-pooling over padding

hidden.mean(dim=1) averages in the pad positions. Correct form:

m = mask.unsqueeze(-1).float()
pooled = (hidden * m).sum(1) / m.sum(1).clamp(min=1e-9)
Truncation silently destroying the label

With truncation=True, max_length=512, the answer span in a QA task, or the decisive clause in a classification task, may be cut off entirely. Always log the fraction of examples that hit truncation. If it is above a few percent, use sliding windows with stride, or a long-context encoder.

Not setting model.eval()

Dropout stays active at p=0.1 in every layer, including on attention weights. Inference becomes stochastic and measurably worse. Also wrap inference in torch.no_grad() / inference_mode() — otherwise you silently build a graph and can OOM on a large batch.

fp16 overflow in attention scores

fp16 max is 65504. Pre-softmax scores can exceed it in a poorly-conditioned or fine-tuned model, giving inf then NaN. Prefer bf16 (same exponent range as fp32), or use torch.finfo(dtype).min for masking rather than -1e9, and enable gradient scaling.

Weight decay applied to LayerNorm and biases

Decaying γ toward 0 shrinks the normalisation scale and degrades training. Standard practice excludes any parameter whose name contains bias, LayerNorm.weight, or layer_norm from the decay group. Most HF example scripts do this; hand-rolled training loops frequently do not.

Reporting a single fine-tuning seed

On datasets under ~10k examples, seed variance on GLUE tasks like RTE and MRPC routinely exceeds the difference between published methods. Run 5–10 seeds and report mean ± std. A single-seed comparison between two methods is not evidence.

Assuming [CLS] is a good sentence embedding

Raw pre-trained [CLS] vectors are highly anisotropic — they occupy a narrow cone, so cosine similarity between any two is high and uninformative. It underperforms averaged GloVe on STS. Use a contrastively fine-tuned model (SBERT, E5, BGE) or apply whitening / flow post-processing.

Position IDs not reset after chunking

When you split a long document into windows, each window must start at position 0 unless you deliberately want continued positions. Passing raw offsets past 511 raises an index error at best; a custom implementation may wrap silently.

Comparing models at different sequence lengths

Latency and quality both depend strongly on T. Benchmarking model A at T=128 against model B at T=512 tells you nothing. Fix T, fix batch size, fix padding strategy (dynamic vs fixed changes throughput by 2–3×), and report all three.
